# 实验项目1：景区指南数据采集与预处理

版本：selected_v2_text_only_1。处理日期：2026-10-28。范围：项目1，网页文字；项目2—7未在本报告中实现。本文按两份原始任务书的项目1评分项组织，不是教师评分结果。

## 1. 实验目标与结果

教师数据尚未发放，本组先自行准备3个景区的官方推荐路线和游客游记。每景区5篇官方路线、5篇游客游记，共30个不同文章页面。单篇中的多个路线章节不拆分计数，不使用生成文本补足数据。

结果：30篇全部采集成功，通过结构与格式检查，导出JSON、JSONL、30份TXT、30份逐块审计及真实变化示例。20项测试全部通过，独立目录从HTML离线重新提取、清洗，64个输出文件与参考结果逐字节一致。检查证明的是本批处理和文件一致性，不是语义抽取准确率。

## 2. 来源选择和获取

官方来源分别为泰山风景名胜区管委会政府网站、张家界世界地质公园管理网站路线栏目、净月潭景区运营方网站。游客来源统一为携程攻略游记。选择依据是独立文章覆盖、正文可获取、存在路线顺序/时间/交通或条件建议，并兼顾天气、体力、家庭与季节差异。

张家界域名按该站管理处自述、联系方式与路线栏目归属记录；前期发现旧链接指向与现站不同，没有把域名归属写成已完成独立认证。净月潭官方文本较短，保留独立页面中明确的路线或时长，不以游记字数阈值误删。JYT_NOTE_005完整游记跨城，净月潭取用段335字，保留实际游览信息并标记较短。

本项目采用“定向选好来源，再按清单爬取”的真实流程，不声称先爬取大规模候选池再统计筛选。前期探测与少量排除案例见[选源记录](../docs/selected_v2_source_selection.md)及`selected_v2_source_review.json`。逐篇URL、题名、景区、类型、发布方、作者、可核日期、XPath和理由见[来源清单](../data/metadata/selected_v2_sources.json)。

采集器逐条请求，开始时间间隔至少2秒，无并发与自动重试；默认优先使用缓存，`--refresh`显式联网。检查HTTP状态、正文节点数量与最小中文内容，不接受登录页、空正文或停止服务提示作为文章。实际30篇均HTTP 200，原始正文精确重复组为0。每篇保存HTML响应、HTTP元数据、采集时间、响应哈希、正文HTML和未归一化文字，以便追溯和离线重建。

## 3. 流程和关键实现

```text
30篇来源清单 → 顺序抓取/本地缓存 → XPath正文定位
  → 有序文字块 → 按配置选择目标景区范围
  → 字符和空白归一化 → 去播放器/占位文本/重复图注
  → 字段、重复、偏移、格式检查 → JSON/JSONL/TXT和审计
  → 独立目录重放及测试
```

### 3.1 正文与范围分开处理

XPath排除导航、文章头尾等网页结构；文字块保留原顺序、角色和XPath，不读图片内容或alt。完整采集文字与提取块的拼接逐篇比较，忽略空白后没有丢字或添字。

11篇游记需进一步选取目标景区范围。配置保留主体游览、相关进出交通与必要住宿背景，排除其他城市/景区的独立行程。外部地名用于交通起终点、比较或计划背景时可以保留，不能用地名黑名单删除整句。未机械删除代词所在段落，原日序不重编号，避免把“计划”误当“实际”。配置按原块编号和少量唯一锚点重放，正文变化、编号越界或锚点歧义立即报错，要求重新审核范围。

范围配置及每篇说明见[scope_rules](../data/metadata/selected_v2_scope_rules.json)，逐块去留及理由在正式输出`audit/`。这是助手逐篇检查后给出的配置，不是学生已做完人工标注的声明，也不是全自动景区相关性分类器。

### 3.2 清洗规则

| 规则 | 做法与保留边界 |
|---|---|
| HTML与网页元数据 | lxml定位正文、跳过script/style等结构，不把标题外导航当正文；来源/作者/日期留在结构字段 |
| 编码与字符 | 已解码文字用Unicode NFC；移除技术控制符、BOM、零宽空格等，保留emoji的ZWJ与含义符号 |
| 空白和换行 | CRLF/CR统一LF；NBSP、全角空格、tab等转普通空格并压缩；块内去空行，块间统一两换行 |
| 网址与异常标点 | 移除正文URL，元数据source_url始终保留；重复中文逗号合并，不批量替换路线破折号/箭头/星级 |
| 媒体控件与占位 | 只删除独立00:00/00:00播放器文字及精确匹配的无信息占位，实际08:00/16:00等不删 |
| 冗余图注 | 图注与前文图注或普通段落完全相同时去除；不对叙述段落去重，保留“又折返”等重复到访 |
| 原文语义 | 不改写景点名、错字、否定、条件、代词、原日序、单位和时刻；不从图片补造缺失信息 |

核心代码位于`capture_selected_sources.py`（get_response/extract_body）、`text_blocks.py`（extract_blocks/block_fingerprint）、`preprocess_selected.py`（scope_blocks/normalize_text/process_document/quality_report）。代码目录为`experiments/exp01_data_preprocessing/src/`。输出文本块偏移满足`clean_text[start:end] == block.text`，单位是Python Unicode字符。

### 3.3 空值、重复和异常字段

必填来源、景区、类型、题名、采集时间、权利说明等逐项校验，日期采用ISO格式，采集时间必须含时区。可空作者和许可链接显式用null，不用空字符串或猜测值填补；异常类型、非法日期或破损输入哈希报错。

清洗文本去空白后做精确重复检测；若重复导致数量不足，不静默删除至不足5+5，本次重复组为0。同景区文章另用字符5-gram集合Jaccard≥0.82给近重复警告，不自动删除，本次警告0组。阈值是去重诊断参数，不是经过标注校准的准确率。

日期优先采用游记详情页显式“发布”标签，其次来源已记录日期/详情日期；列表日期单独保留。本批4篇有日期候选冲突，分别是TS_NOTE_004、ZJJ_NOTE_003、ZJJ_NOTE_004、JYT_NOTE_002。不能用列表值直接覆盖详情发布值，也不把它们当作独立核实的首次发表日期。

## 6. 实际问题、处理和局限

1. **长游记的全文长度虚高。** 把跨城全文当目标景区语料会污染后续地点和路线统计。处理：逐篇范围选择并保存块级审计；完整原文不覆盖。局限：当前范围配置绑定这30篇，不是通用相关性模型，新增文章要重新核查。
2. **去重容易损害实际路线。** 相同景点反复出现可能是折返而非重复垃圾。处理：只删完全重复图注，保留正文重复到访；ZJJ_NOTE_001回归检查仍含“又折返”和“只走到”。
3. **原文和元数据会冲突。** TS_NOTE_004从23:00到次日01:40相差160分钟，原文却写03小时40分钟（220分钟）。保留两者并标记，不擅自选一个改正。另记录“天外天客运站”用名及“金鞭溪索道”图注待核问题；日期冲突另保留所有依据。
4. **图片可能含重要路线信息。** 按组长决定本轮纯文本处理，图中独有信息明确排除，没有用AI编写替代文字。后续若研究多模态采集，应作为新版本单独设计。

短官方路线与335字的游客片段虽满足当前文档来源口径，但实体/共指等表达不均衡。总量、清洗格式与可复现性不能保证后续抽取效果，需要对应实验建立真实人工评估集。历史票价、封闭信息和个人体验不视为当前出游事实。

## 7. 输出接口和下游交接

统一输入为`data/processed/full/selected_v2/dataset.json`及同内容JSONL。基础字段包括doc_id、scenic_id/scenic_name、text_type、title、source_url、publisher、author、published_at、collected_at、content_scope、raw_text、clean_text、license/license_url、notes；新增blocks、metrics、日期候选、哈希及疑点字段。

其中raw_text是所选景区范围的归一化前文字，完整跨城文章在`data/raw/full/selected_v2/`。JSON可用标准库直接读取，满足任务书Excel/CSV/JSON的结构化输出要求，不依赖Excel。接口和接入说明见[数据接口](../docs/data_contract.md)、[交接说明](../docs/handoff.md)。证据索引基于clean_text；当前没有新30篇的实体/路线/共指/条件关系金标准。远端项目2已有黄山初版，其基础字段兼容，但还需更换景区筛选参数、扩充词表并去除黄山硬编码统计标签，不能仅换输入路径就宣称完成新景区适配。

按组长确认，正式清洗输出`data/processed/full/selected_v2/`已纳入Git，拉取后可直接供后续项目读取；完整采集原文、HTML和复现缓存仍保留在本地交接包。所有文本沿用原来源权利说明，没有套用统一开放数据许可证。
