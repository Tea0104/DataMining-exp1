# 实验二逐项验收说明

实验：游览步骤的实体识别。状态：黄山单景区初版已完成，实体产出、词频图与名称级评估可复现，等待组员人工复核；本说明随 PR 提交。

本次仅处理黄山`HS_OFF_001`与`HS_NOTE_001`两条清洗文本，共2847字，故宫与西湖样本未接入。下列分值来自任务书，表示验收项权重，不是自评得分。

## 一 实体类型定义与规范 15分

**1．三类实体的定义 边界和示例（10分）**

三类实体按可验证的句法位置定义：景点POI是能被“到、去、经过、住在”支配且有可识别名称的地点，分15个子类型，含山峰、峡谷、步道段、亭、住宿与餐饮；交通方式是能与“乘坐、坐、走、骑”搭配、回答“怎么移动”的词，分5类；时间节点是能回答“什么时候”或“花了多久”的表达，分5类。[规范表][spec]。

判定边界用11条规则固定，例如索道线路名一律归交通方式而不重复计入POI，`前山`这类方位区域计入而`山顶`这类方位通名不计，`1100+CNY`与`1000年`不判为时刻，`一日游`作为路线产品名不判时间。[规范表][spec]。每条规则在机读词表里还附带一句判定理由，例如`西海大峡谷北入口`注明“最长匹配优先于西海大峡谷”。[词表][lexicon]。

**2．定义在多景区之间保持一致并说明易混淆情况（5分）**

易混淆情况按12组列出并给处置，如`云谷索道`与`云谷寺`、`光明顶`与`光明顶山庄`、`猴子观海`与片段`观海`、`小火车`与`火车`。[规范表][spec]。但一致性只覆盖黄山：词表顶层把`scenic_scope`写作`huangshan`，后缀表也不含故宫的`殿`、`宫`与西湖的`荷区`、`堤`、`桥`。[词表][lexicon]。

实测直接换景区会失效：故宫两篇只输出10条、6个唯一名，其中`门楼`、`香亭`为通名误判；西湖两篇只输出5条，唯一POI是误判的`风景区`。任务书要求的“对比多个景区归纳类型体系”本轮未做，原因也在此——这套类型与词表是从黄山长出来的，没有经过跨景区校验。[加载逻辑][load]。

## 二 实体识别方法实现 35分

**3．采用Jieba加自定义词典或规则方法完成三类识别（15分）**

先用`register_lexicon`把55个词条以频次20000写入jieba自定义词典，再用`tokenize`取带偏移的切分结果，最后按“词表优先、闭类词次之、四位时刻再次、后缀兜底”的顺序判定；候选重叠时由`resolve_overlaps`按长实体优先、同跨度POI>交通>时间取值。[词典注入][register]、[判定][detect]、[去冲突][resolve]。

黄山两条文本最终输出100条mention，三类分别为65、23、12条。[实体文件][entities]。位置约束在`extract`末尾逐条断言，不是抽样检查。

**4．词典与规则覆盖景区专属词与常见表达（10分）**

词典55条，其中POI 31、交通13、时间11，覆盖`西海大峡谷北入口`、`光明顶山庄`、`东黄山旅游度假区`、`西海观光缆车`这类长词；停用词26条抑制通名、12条拦截被切开的景区名前缀、1条排除跨城地点；数字规则用后8字符上下文排除价格、树龄与焦距。[词表][lexicon]、[停用词][stop]、[规则][detect]。

已知缺口是`小火车`未收，被切成`小`与`火车`后由`火车`命中词表，产生1个误识和1个漏识，这也是全量评估里唯一的错误。[评估结果][eval]。另外停用词是精确词匹配，`西海`被整体拦截，当前语料里它是碎片，但换一批文本若出现真实片区名“西海”，会被静默丢弃。

**5．批量处理多个景区文本（6分）**

程序在单个景区内按篇循环，`extract`对每条记录独立处理并累加，两篇文本均完整走完流程。[批量循环][extract]。但不支持一次处理多个景区：`--scenic`是单值参数，`summarize`把`scenic_id`写成常量`huangshan`，输出文件名也不带景区标识。[汇总][summarize]。

因此连续对故宫、西湖运行并指向同一输出目录时，后一次会覆盖前一次，统计里的景区标签仍是黄山。这一项目前只满足“同景区多篇”，不满足“多景区”。

**6．保留实体类型 来源及出现位置（4分）**

每条实体保存11个字段：`doc_id`、`scenic_id`、`text`、`entity_type`、`subtype`、`granularity`、`canonical`、`start`、`end`、`sentence_id`、`method`。[字段构造][extract]。位置采用`clean_text`的Python字符索引、左闭右开，句号由`split_sentences`按句末标点与换行切分后落位。[切句][sent]。

来源不直接写进实体，用`doc_id`回溯`data/metadata/sources.json`里的网址、发布方与许可，这样同一来源的信息不必在每条实体上重复；代价是单独拿到`entities_v2.json`看不到出处。

## 三 识别结果与质量检查 20分

**7．输出结构化实体文件且字段清晰（8分）**

输出为UTF-8、LF换行、两空格缩进的JSON数组，另配`stats_v2.json`记录分类型、分类别、粒度分布与逐篇计数。[导出][main2]、[统计][summarize]。100条记录的位置全部满足切片断言，按`doc_id`、`start`、`end`无重复。

两点需要说明：没有JSON Schema校验，位置正确性只靠代码内断言；两版`subtype`语义不同，v1是占位值`mode`、`suffix`，v2才是语义值，混用会出错。

**8．人工抽查并分析误识 漏识与歧义（8分）**

抽查记录覆盖v1全部97条与v2全部100条，按词片段、通名误判、跨出景区、数字误判、交通边界五类归并，逐条给出原文片段、实际输出与应得结果，另列8个典型错例与10条正例。[抽查记录][manual]。量化部分用55项名称级金标计算，v2总体精确率0.98、覆盖率0.98，仅`小火车`一处错。[评估][eval]。

有两点必须说明：抽查由助手初查，未经组员签字；金标与词表同源，0.98是上限值而非泛化准确率，真正可信的是v1到v2的提升。[迭代记录][iter]。

**9．结果无明显大规模噪声 重复或类型混乱（4分）**

`resolve_overlaps`保证同一文档内实体区间两两不重叠，切分位置本身唯一，因此没有重复记录。[去冲突][resolve]。残留三处需要验收人判断：`小火车`被切成`火车`属边界错误；`徽味楼`按行程节点计入POI，子类型是餐馆；`谷底`是通名，却作为峡谷底部换乘点保留。三处均已在抽查文档中标注，不属于大规模噪声。

## 四 词频可视化与迭代优化 20分

**10．统计三类实体词频并生成可视化（10分）**

按类型、表面形式、上位类别三列计数输出CSV，并绘三联横向柱状图，每类取Top10、标注次数、刻度取整，字体加载微软雅黑以正常显示中文。[词频][freq]、[绘图][plot]。

图按原文表面形式统计，具名索道不与泛称合并：`索道`10次是泛称，`云谷索道`与`玉屏索道`各2次、`太平索道`与`西海观光缆车`各1次单列，图注说明类别汇总在`stats`的`by_canonical`。[图表][png2]。未做词云，条款为“词云或柱状图”，柱状图已满足，也避免了引入额外依赖。

**11．依据可视化调整词典 停用词并说明前后变化（10分）**

v1只靠后缀与数字规则，词频图显示POI榜首是`西海`10次、`宾馆`5次，交通榜`索道`15次，时间榜出现`1100`与`1000`，说明问题是切碎与通名误判，而非识别不出。[v1对比图][png1]。

据此做三项改动：写入55词词典、补26+12+1条停用词、把数字规则收紧为四位加上下文否定并新增`T + 1`正则。[改动清单][iter]、[规则][detect]。同一金标下v1为0.43与0.36，v2为0.98与0.98，两版图并列可见POI榜首从`西海`变为`光明顶`8次。[v2对比图][png2]。

## 五 报告与可复现性 10分

**12．说明方法 参数 运行方式 输入输出与代表性结果（10分）**

依赖Python 3.10以上、`jieba`与`matplotlib`，本次实际使用Python 3.12.14；从仓库根目录执行下列命令，读取`data/processed/sample_v1.json`，产物写入本实验`outputs/`。[运行说明][readme]。

```bash
python experiments/exp02_entity_recognition/src/recognize_entities.py --version v1
python experiments/exp02_entity_recognition/src/recognize_entities.py --version v2
python experiments/exp02_entity_recognition/src/evaluate.py
```

在独立目录重跑三条命令，输出与仓库内文件逐字节一致，说明流程不依赖当前工作目录。[运行说明][readme]。缺口是没有`requirements.txt`锁版本、字体路径硬编码`C:\Windows\Fonts\msyh.ttc`（缺失时回退，可能显示方块）、没有测试与CI，也还没有合并成正式实验报告。

## 人工确认时需要了解的边界

本轮只覆盖黄山两条共2847字、55个名称级金标，不能据此估计泛化性能；故宫与西湖实测会大面积漏识，换景区需要重写词表。v2的0.98来自与词表同源的金标，真正可信的是v1到v2的提升，因为v1不使用词表，是独立基线。`小火车`仍被识别为`火车`，保留为已知失败案例。`outputs/gold_huangshan.json`与`outputs/manual_check.md`为助手初标，提交前需组员抽检20条并签字。评估为名称级，不评位置级正确性，也不评同形异义。实验一后续扩充的30篇语料尚未接入本实验，接入后需要重跑并重新标注金标。
