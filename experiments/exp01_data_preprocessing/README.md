# 景区指南数据采集与预处理

已建立首轮开发样本：3个景区各1条官方路线、1篇游客游记的选定正文，共6条。完整语料尚在扩充，项目1未按完整数据量验收。

## 依赖

Python 3.10或以上，仅使用标准库。清洗不调用大模型，也不需要模型密钥。

## 离线重建清洗数据

在仓库根目录运行：

```bash
python experiments/exp01_data_preprocessing/src/preprocess.py
```

输入：`data/raw/sample_v1/*.json`。

输出：`data/processed/sample_v1.json`、同名JSONL、独立文本和 `data/metadata/` 中的来源、质量报告。输出包含清洗前后的正文，便于检查规则效果。

## 重新下载候选来源

```bash
python experiments/exp01_data_preprocessing/src/collect_sources.py
```

该脚本根据来源清单逐条尝试获取页面，将结果及访问状态写到默认被Git忽略的 `data/downloads/`，不会覆盖人工确认的正文范围。原站受访问限制时记录失败，不将错误页当作正文，不尝试绕过验证码或访问控制。

页面内容选取位置和人工摘录范围见 `data/README.md`。后续扩充时先检查原文、范围和字段，再加入新的版本；当前构建脚本会检查首轮样本应为6条，不直接用来验收全量数据。

## 清洗规则

1. HTMLParser提取文字，过滤脚本、样式和嵌入框架，保留段落边界。
2. 使用Unicode NFC，不把景点名称、全角标点或表情强制改写。
3. 移除正文网址，统一回车换行、空格与不间断空格，去除BOM、零宽空格和非文本控制符。原始正文和来源网址另行保留。
4. 保留原文的条件、代词、路线连接符、编号、价格与时间，交由后续实验判断含义。
5. 检查3个景区的类型数量、唯一编号、必填字段、重复正文、乱码、脚本残留及归一化幂等性。
