# 黄山景区实体定义规范表（实验二）

本规范用于把黄山游览文本中的实体统一为三类：**景点 POI、交通方式、时间节点**。
规范先行于代码：`src/config/lexicon.json` 是它的机读版本，`src/recognize_entities.py` 只负责按本表执行。

## 1. 适用范围与位置口径

- 适用范围：`scenic_id = huangshan` 的两条清洗文本（`HS_OFF_001` 官方路线、`HS_NOTE_001` 游客游记）。
- 文本来源：`data/processed/sample_v1.json` 的 `clean_text`，**不再做任何二次清洗**。
- 位置口径：`start` / `end` 为 Python Unicode 字符索引，左闭右开，必须满足
  `clean_text[start:end] == text`。不使用字节偏移或 UTF-16 长度。
- 记录粒度：以“一次出现”为单位（mention），同一名称出现多次即多条记录；
  名称级去重只在评估时使用。

## 2. 三类实体定义

### 2.1 景点 POI

| 子类型 | 说明 | 示例 |
|---|---|---|
| `peak` | 有名称的山峰 | 始信峰、丹霞峰、光明顶、鳌鱼峰 |
| `canyon` | 有名称的峡谷 | 西海大峡谷 |
| `entrance` | 有名称的出入口 | 西海大峡谷北入口 |
| `trail` | 有名称的步道分段 | 一环、二环 |
| `canyon_bottom` | 峡谷底部换乘节点 | 谷底 |
| `pavilion` | 供休息/观景的亭 | 排云亭、海心亭、莲花亭、蘑菇亭 |
| `viewpoint` | 有名称的观景点 | 猴子观海 |
| `landmark` | 地标性景物 | 飞来石、迎客松 |
| `passage` | 有名称的狭窄通道 | 一线天 |
| `gate` | 入口寺庙 | 云谷寺 |
| `area` | 片区或方位性区域名 | 天海、后山、前山、玉屏景区 |
| `lodging` | 住宿设施（作为行程节点） | 西海饭店、北海宾馆、光明顶山庄、天海宾馆、玉屏楼宾馆、排云楼宾馆 |
| `restaurant` | 餐饮设施（作为行程节点） | 徽味楼 |
| `town` | 景区门口的镇区 | 汤口 |
| `resort` | 周边度假区 | 东黄山旅游度假区 |

判定依据：**能被“到/去/经过/上/下/住在”支配的具体地点**，且具有可识别的名称。

### 2.2 交通方式

| 子类型 | 说明 | 示例 |
|---|---|---|
| `cableway` | 索道或缆车（含线路名与泛称） | 云谷索道、太平索道、玉屏索道、西海观光缆车、索道、缆车 |
| `shuttle` | 摆渡车、接送车 | 大巴、面包车 |
| `rail` | 铁路 | 火车 |
| `self_drive` | 自驾 | 自驾 |
| `walk` | 步行游览 | 徒步、步行 |

判定依据：**能与“乘坐/坐/走/骑”搭配，回答“怎么移动”**。

### 2.3 时间节点

| 子类型 | 说明 | 示例 |
|---|---|---|
| `period` | 时段 | 早上、上午、中午、下午、傍晚、晚上、当晚 |
| `event` | 以自然事件表达的时间 | 日出、日落 |
| `day` | 行程日/相对日 | 第二天、T + 1 |
| `duration` | 行程时长 | 两天 |
| `clock` | 具体时刻（四位数字） | 2100 |

判定依据：**能回答“什么时候”或“花了多久”**，且不依附于价格、长度、年龄等数值。

## 3. 边界规则

1. **最长匹配优先**：`西海大峡谷北入口` 不再拆出 `西海大峡谷`；`光明顶山庄` 不再拆出 `光明顶`。
2. **交通设施不单独成实体**：`索道站`、`索道上站`、`索道下站`、`索道入口` 属于设施描述，
   不另计实体；其中的 `索道` 按交通方式计。
3. **索道线路名归交通方式**：`云谷索道` 等既像地点又像工具的，一律归交通方式，**不重复计入 POI**。
   对应的地点用 `云谷寺` 表达。
4. **方位区域计入 POI，方位通名不计**：`前山`、`后山` 计入；`山上`、`山顶`、`山脚`、`半山腰` 不计。
5. **住宿、餐饮作为行程节点计入 POI**，用 `lodging` / `restaurant` 区分，避免与自然景点混为一类。
6. **无名称通名不标注**：`观景台`、`平台`、`景区`、`酒店`、`宾馆`（孤立出现时）等不计。
7. **时间数字需要上下文校验**：四位数字只有在合理时刻范围且后文不含 `元/CNY/年/MM` 等量词时才计为 `clock`。
   `1100+CNY`（价格）、`1000年`（树龄）、`200MM`（焦距）均不标注。
8. **路线产品名不计时间**：`一日游线路` 中的 `一日游` 是路线标题，不作时间节点。
9. **景区外地点不计 POI**：`上海` 是跨城交通目的地，不纳入景区游览节点。
10. **不为凑数补写**：原文没有的时间、条件、先行词一律不补；未知即未知。
11. **`canonical` 不是实体 ID**：它只表示上位类别，用于统计和图谱 Schema 分层。
    建节点、做路线解析必须用 `text`（去空白后），否则 `云谷索道` 与 `玉屏索道` 会因同类而被合并，
    上山与下山两条不同索道就分不开了。

## 3.1 粒度分层

同一条交通线路可以有两种说法，二者**必须共存**，不能合并：

| 原文 | `text` | `granularity` | `canonical` | 含义 |
|---|---|---|---|---|
| 乘坐**云谷索道**上山 | `云谷索道` | `specific` | `索道` | 具名线路，上山的这一条 |
| 乘坐**玉屏索道**下山 | `玉屏索道` | `specific` | `索道` | 具名线路，下山的另一条 |
| 上下山全部选择**索道** | `索道` | `generic` | `索道` | 只说了方式，没说哪条 |
| 坐官方的大巴 | `大巴` | `generic` | `大巴` | 类别词，本景区无专名 |

- 统计与建图时：`specific` 用于实体与节点，`generic` 用于类别汇总，两者**不互相覆盖**。
- 指代判断（“索道上山”里的索道到底指哪条）**不在实验二处理**，交给项目 4 的共指消解，避免凭空猜测。
- `granularity = unknown` 表示该实体由后缀规则产生、词表未收录，边界需人工复核。

## 4. 易混淆对照

| 原文表达 | 正确标注 | 常见错误 | 原因 |
|---|---|---|---|
| 西海大峡谷北入口 | POI / entrance | 拆成 `西海` + `大峡谷` | jieba 默认词典无该长词 |
| 西海大峡谷 | POI / canyon | 只识别 `西海` 或 `大峡谷` | 前缀被误当独立地名 |
| 云谷索道 | TRANSPORT / cableway | `云谷` 记 POI、`索道` 记交通 | 词被切碎后各自命中后缀 |
| 云谷寺 | POI / gate | 与 `云谷索道` 混淆 | 名称前缀相同、类型不同 |
| 光明顶 / 光明顶山庄 | POI / peak 与 POI / lodging | 只识别 `光明顶` | 长词未进词典 |
| 天海 / 天海宾馆 | POI / area 与 POI / lodging | 识别成 `天海` + `宾馆` | 同上 |
| 猴子观海 | POI / viewpoint | 识别成 `观海` | 四字景点被切分 |
| 小火车 | TRANSPORT / rail | 只命中 `火车` | 边界切分错误（v2 仍存在） |
| 山顶 | 不标注 | 记为 POI | 方位通名被当作景点 |
| 观景台 | 不标注 | 记为 POI | 设施通名无名称 |
| 1100+CNY、1000年 | 不标注 | 记为时刻 | 数字规则缺少上下文 |
| 上海 | 不标注 | 记为 POI | 后缀触发，跨出景区范围 |

## 5. 记录字段

| 字段 | 说明 |
|---|---|
| `doc_id` | 文本编号，与样本一致 |
| `scenic_id` | 固定为 `huangshan` |
| `text` | 实体表面形式，必须等于 `clean_text[start:end]` |
| `entity_type` | `POI` / `TRANSPORT` / `TIME` |
| `subtype` | 上表中的语义子类型（v1 为占位值，v2 起生效） |
| `granularity` | `specific` 具名实例 / `generic` 泛称类别 / `unknown` 词表未收录需复核 |
| `canonical` | 上位类别名；无上位类别时等于 `text`。**不可作为实体 ID** |
| `start` / `end` | 左闭右开字符索引 |
| `sentence_id` | 所在句编号（按句末标点与换行切分） |
| `method` | 命中方式：`lexicon` / `suffix` / `keyword` / `number` / `regex_day` |

## 6. 与其他实验的衔接

- 项目 3（路线层级）可直接使用本表的 `POI` 作为节点，`TRANSPORT` 作为步骤方式。
- 项目 4（共指消解）可把本表实体作为“最近名词”候选，但**不要**把 `PREP + 这里` 之类的泛指直接当作先行词。
- 项目 6（图谱）建议节点类型直接沿用 `entity_type`，子类型作为节点属性。
- 若后续换成多景区数据，只需扩充 `lexicon.json` 与 `stopwords.json`，代码与字段不变。
